# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A power assurance check and engine trend log for helicopter crews, read from
the digitised flight-manual charts. It ships as a single self-contained
`index.html` on GitHub Pages, installs as a PWA, and computes with no network.

It is a trending aid, not a maintenance record. That constraint drives most of
the rules below.

## Commands

```
npm install
npm run check     # build && test && smoke — run this before committing
npm run build     # bundles entry.jsx into index.html, writes sw.js
npm test          # every chart against its published example, plus the off-chart gate
npm run smoke     # loads the built index.html in Chromium and drives every aircraft
npm run icons     # re-renders the PNG icons from icons/icon.svg
```

There is no linter or formatter configured.

`npm run smoke` needs a Chromium. Set `CHROMIUM_PATH` to point at an existing
one instead of `npx playwright install chromium`.

### Running one test

`test/charts.test.mjs` is a plain script with no filter argument — it walks
every aircraft in the registry. To check one thing, import the registry
directly (it is plain ESM, no build step):

```
node -e 'import("./src/aircraft/index.js").then(m => {
  const a = m.byId("bell-407");
  const { chart } = m.chartFor(a, m.defaultConfig(a));
  console.log(m.checkFor(a).compute({ chart, aircraft: a, oat: 10, pa: 6000, tq: 70, mgt: 600 }));
})'
```

This works only because the computing half of each aircraft is React-free —
see *The .jsx split* below.

## `index.html` and `sw.js` are committed build output

`index.html` is the whole site: React, Recharts, the chart data and the app,
all inlined. It and `sw.js` are generated by `npm run build` and **committed**.
CI rebuilds and fails if either differs from what was committed, so a source
change without a rebuild cannot reach the site. Always run `npm run build` and
commit both files alongside any `src/` or `entry.jsx` change.

The build entry is `entry.jsx`, not `src/App.jsx`. `entry.jsx` supplies
`window.storage`, the async key/value store the app persists through, backed by
`localStorage`. Building `src/App.jsx` directly gives a page that renders but
never saves a log.

The build id in the footer is a hash of the sources, not the clock — the build
must stay reproducible for the CI staleness check to work.

## Architecture

```
src/engine/            arithmetic with no aircraft in it: interp, atmosphere, format
src/aircraft/index.js  the registry — AIRCRAFT, chart lookup, option scope, seriesKey
src/aircraft/<id>/     one folder per type, everything about that type inside it
    index.js             the definition: inputs, options, meta, frame, verify
    charts.json          the digitised chart data
    powercheck.js        the check as that type's manual walks it — no React
    view.jsx             the drawing half — Chart and drawCard
src/views.js           maps aircraft id -> its view.jsx
src/App.jsx            the UI, which knows about no aircraft specifically
src/pick.jsx           the aircraft page the app opens on
src/css.js             all styles, as one template string
```

**Nothing is shared between types.** Two aircraft whose charts happen to have
the same shape still get a `powercheck.js` apiece — a change made for one must
not reach the other, and the next revision of one manual may diverge. Only
`src/engine/` is shared, and only because it contains no aircraft.

Note the README's "Layout" section and `docs/adding-an-aircraft.md` still
describe an older layout (`src/procedures/`, `src/aircraft/<id>.charts.json`).
The per-aircraft folders above are what the code actually does; the rest of
those docs is current.

### The check contract

`powercheck.js` exports three things, and `App.jsx` needs nothing else:

| export | contract |
|---|---|
| `compute({ chart, aircraft, ...readings })` | `{ margin, stats: [{label, value}], notes: [string] }`, plus whatever else the aircraft logs |
| `axes(chart)` | the domain of each axis, derived from the chart data |
| `offChart({ chart, ...readings })` | `[]` when every reading is on the chart, else a plain sentence per reading that is not |

`view.jsx` beside it exports `Chart` and `drawCard`, registered in
`src/views.js`.

### The .jsx split

The computing half of an aircraft must never import React. Node cannot import
`.jsx`, and `test/charts.test.mjs` imports `src/aircraft/index.js` directly to
run the chart maths with no build step. Keep drawing in `view.jsx`.

## Rules that produce a wrong answer quietly if broken

**`offChart` is not optional.** `src/engine/interp.js` fits a line through the
two bracketing points and keeps going past the ends of a curve — it does not
clamp, and past the end it reads *optimistic*. Torque typed as `700` instead of
`70` computed a confident +3381 °C margin before the gate existed. Every
procedure refuses to answer off its own grid, and the bounds are derived from
the chart data so re-digitising moves them.

**Option scope partitions the trend.** An option with `scope: "check"` is a
property of *this* check (which engine was measured) and splits the trend line
via `seriesKey`; an option without a scope is fitted to the airframe (inlet,
snow deflectors) and does not, because that is a step in one engine's life.
Only put in `options` what the manual itself distinguishes — the 407's chart is
headed *hover or level flight*, so how it was flown is a condition in `meta.cond`,
not an option.

**`noChart` must be the exact complement of `variantFor` returning `null`.**
`npm test` asserts this across every combination of an aircraft's options.

**Per-type values may not be shared objects.** `frame`, `gauge`, `marginUnit`,
`marginLabel` are each aircraft's own — the test suite checks object identity,
because a shared default is how one type's scales silently get drawn under
another type's data. A margin in °C of MGT off a 407 nomogram and one in °C of
ITT off a 212 table are not the same quantity.

**Every chart in `verify[]` is the acceptance test.** Each entry is the worked
example printed beside that chart in the manual; `npm test` fails if the app is
more than 1 °C (or 0.1 % on torque/N1) from the printed answer. A digitising
slip shows up here, and CI will not deploy past it.

## Language the app is allowed to use

The app makes no airworthiness statement. A positive margin carries no verdict
at all; a negative one reads *"Over the chart maximum"*, which is about the
chart, not the aircraft. Any judgement band beyond that belongs to one operator
or one manual and must say whose it is — `watchBelow` requires `watchNote`, and
a `kMin` cut-off that can withhold an answer requires `kMinNote`. The test
suite enforces both. Do not add a shared default threshold.

## Where the reasoning lives

- `docs/adding-an-aircraft.md` — the full recipe for a new type, including the chart JSON shape
- `docs/pending-charts.md` — the eighteen manual pages received, what each still needs, and the rules transcribed from them
- `docs/engineering-review.md` — the self-audit against the manuals, and the operator engineer's rulings on the open items
- `DESIGN.md` — the visual system as the code actually uses it: palette and what each color is allowed to claim, the type scale, why there are rules and no shadows, and the measured accessibility gaps

The `ui-ux` skill in `.claude/skills/` reads `DESIGN.md` before any interface
work, so extend the tokens there rather than inventing new ones.

Comments in this codebase record *why* rather than what, often naming the bug
that motivated a line. Match that when editing.

## Service worker

`sw.template.js` is the source; `sw.js` is generated with `__VERSION__`
replaced by a hash of `index.html`. Precaching uses `cache: "reload"`
deliberately — GitHub Pages serves the page with `max-age=600`, and without the
bypass a new worker re-caches the very page it was meant to replace, leaving an
installed app on a stale version indefinitely. The app never reloads on its own;
it offers a **Restart now** bar, because a reload would discard a check being typed.
